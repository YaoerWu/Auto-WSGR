# 任务书：配置树框架

## 1. 目标

把散落在各模块的配置模型收成**一棵可继承、可整体覆盖的配置树**，让用户只改一个
usersettings.yaml 就能改所有模块的配置，并把这棵树作为 GUI 读取配置的唯一出口。

本期同时落地第一份真正的模块配置：换船模块的舰名映射表。

## 2. 范围

### 做

- 建立模块配置基类 ModuleConfig，统一 frozen + extra=forbid。
- LogConfig / DeviceConfig 改为继承 ModuleConfig。
- 新建 FleetSelectConfig，承载舰名映射表。
- UserConfig 换成新树：LOG / DEVICE / FLEET_SELECT。
- usersettings.yaml 重写成新格式。
- 规范补配置字段命名条款。

### 不做

- 不修 launcher.py / server 里读旧字段的调用方，等 runtime 层重写。
- 不删旧配置类（AccountConfig / OCRConfig / NormalFightTaskConfig /
  DailyAutomationConfig / DecisiveConfig），原样留在 config.py。
- 不做 VisionConfig：模板置信度这类值用户基本上不会改，留在模块常量里。
- 不做「用户 config 与模块默认的深合并」之外的优先级机制。

## 3. 设计

### 3.1 命名

配置模型字段统一 UPPER_SNAKE_CASE，与模块常量保持一致；YAML 键名因此全大写。
模块前缀用于区分归属（LOG_ / SCRCPY_ / DEVICE_ / ADB_）。

### 3.2 继承

    ModuleConfig  (frozen=True, extra='forbid')
      ├── LogConfig          common.system
      ├── DeviceConfig       common.device
      ├── FleetSelectConfig  application.fleet_select
      └── UserConfig         顶层聚合

UserConfig 本身也继承 ModuleConfig，所以整棵树都不可变、都不接受未声明字段。
未在 YAML 里出现的字段自动用模块默认值——这就是「只需要覆盖想改的那几个」的实现方式，
不需要额外写合并逻辑。

### 3.3 舰名映射

FLEET_SELECT.SHIP_NAME_MAP 的形状是 自定义船名 -> 系统标准船名：

    SHIP_NAME_MAP:
      希尔德布兰德: AIII
      U-47·狼群: U-47
      狼群: U-47

也接受多行文本（宽泛校验）：一行一组，左边自定义名、右边系统名，中英文冒号都认，
左侧多个自定义名用中英文逗号分隔，展开成多条映射。

    希尔德布兰德: AIII
    契卡洛夫：85工程
    U-47·狼群,狼群: U-47

两条使用规则（由调用方直接查表，配置模型上不开业务方法）：

- 识别：OCR 读到自定义名时用 `SHIP_NAME_MAP.get(text, text)` 还原成系统标准名。
- 搜索：已知系统标准名时反向查第一个登记的自定义名去搜，未登记则用系统名。

### 3.4 配置模型编排

所有配置模型统一遵守 `docs/features/[规范]python-code-style.md` §6.6：文件放模块根目录、
固定六段骨架、类内只有字段和校验方法、字段行尾注释、可变默认值用 `default_factory`、
配置里不写业务方法。
