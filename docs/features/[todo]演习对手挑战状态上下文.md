## 1. 为什么要这份上下文

演习页右侧有 5 个对手，挑战过的对手按钮会变灰。现在每打一场都要重新识别一遍整个列表：
先判列表在不在顶部、再逐格匹配挑战按钮、再滑到底、再匹配一次。一个上午打十几场，重复几十次识别。

用户 2026-10-30 的原话（要点）：

> 进入演习页确认到达后先识别顶部四个位置能否匹配挑战模板（打过的匹配失败）→ 滑到底 →
> 识别滑动后第 4 位置（对手 5）→ 存程序级上下文；业务层每打一场更新；
> 每天 0/12/18 点刷新清空；冷启动首次进入重建；终止后首次进入重建。

所以这件事拆成两半：

- **导航层 / UI 控制器**：提供「现在这一帧，哪几格还能打」的读取能力和点击能力（本阶段已备好素材，未使用）；
- **业务层**：维护跨步骤的上下文、决定什么时候必须重建。
