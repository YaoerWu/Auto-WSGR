## 3. 模板使用规则（三条硬规则）

### 3.1 规则一：手画框只用来"指位置"，坐标以程序测的为准

四个「挑战」按钮的蓝色块实测**完全一致**：161x55，x 从 1001 到 1162，y 起点 124 / 272 / 420 / 568，行距 148；模板相对按钮左上偏移 (+34, +9)。

用户手画的红框在位置 2、3 偏了约 3px，位置 4 偏得更多。照红框 +1px 做 ROI 的实测匹配分数是 1.0 / 0.86 / 0.86 / **0.37** —— 后三个全废。

**结论**：所有 `template_px` 一律以程序在干净图上的精确匹配位置为准；红框只用来告诉"这里有个东西"。

### 3.2 规则二：判据与点击定位必须分开

跨 60+ 张静态图扫误命中（`TM_CCOEFF_NORMED`，阈值 `OPENCV_TEMPLATE_CONFIDENCE = 0.85`）：

| 模板 | 真实页 | 最高误命中 | 允许用途 |
| --- | --- | --- | --- |
| `overlay_title` | 1.0 | **0.4561** | ✅ **唯一浮窗判据** |
| `overlay_refresh` | 1.0 | 0.5212 | 点击定位（可辅助确认） |
| `rival_button` | 1.0（演习页四处全 1.0） | 0.5954 | 判"这一格能不能打"；灰态只有 **0.112**，可区分已挑战 |
| `overlay_challenge` | 1.0 | **0.7839**（无浮窗的演习页） | ❌ 不作判据，只作点击定位 |
| `overlay_close` | 1.0 | **0.9536**（登录更新弹窗）、0.8914 / 0.8913 / 0.8901（每日公告、奖励确认、奖励浮窗） | ❌ 不作判据，只作点击定位 |

**硬规则**：

- `EXERCISE_RIVAL_CONFIRM` 只认 `overlay_title`。关闭按钮在所有浮动弹窗上都有，拿它判层会把登录弹窗、每日公告全认成演习浮窗。
- 浮窗里的「挑战」在无浮窗演习页上有 0.7838，离阈值只差 0.07 —— 不能当存在判据。
- `rival_button` 在灰态（已挑战）上只有 0.112，正好用来回答"这一格还能不能打"，供"选第一个可挑战对手"使用。

### 3.3 规则三：一次截图判多件事

浮窗在不在、演习标签有没有激活 —— 合并成一次 `expect_template`（模板元组 + ROI 元组），
从 `RecognitionResult.observation` 按顺序取，不要一个检查截一次图。

落地形态：`read_sortie_layer` 一次读 6 个模板（浮窗标题 + 五个 tab），
返回**这一帧能看到的全部层**的元组；和主页 `read_home_layer`、准备页 `read_battle_preparation_layer` 保持同一签名。

## 4. 设计

### 4.1 域探针：一帧读完整族，返回这一帧能看到的全部层

三个域探针签名统一为 `(ctx, *, attempts, interval_seconds) -> tuple[PageName, ...]`，**由深到浅**返回全部层：

| 探针 | 覆盖页面 | 一帧读几个模板 |
| --- | --- | --- |
| `checker/home/checker.py::read_home_layer` | `HOME_REWARD_CONFIRM` / `HOME_REWARD` / `HOME_NEWS` / `HOME` | 7 |
| `checker/sortie/checker.py::read_sortie_layer` | `EXERCISE_RIVAL_CONFIRM` / `SORTIE_MAP` / `EXERCISE` / `EXPEDITION` / `CAMPAIGN` / `DECISIVE_BATTLE` | 6 |
| `checker/sortie/battle_preparation/checker.py::read_battle_preparation_layer` | `EXERCISE_PREPARATION` / `DECISIVE_BATTLE_PREPARATION` / `CAMPAIGN_PREPARATION` / `BATTLE_PREPARATION` | 4（共用一个 ROI） |

**为什么返回元组而不是单层**：浮窗出现时顶部标签栏没被遮住，演习浮窗开着的时候
`(EXERCISE_RIVAL_CONFIRM, EXERCISE)` 两层同时在画面上。只返回一层会丢掉「栈该压几层」这个事实；
返回元组后栈自然是 `[.., 演习, 浮窗]`，`navigate_back()` 天然就是关浮窗。

`registry.probe_domains(ctx)` 把三个探针拼起来：

```python
hits: list[PageName] = []
for prober in _DOMAIN_PROBERS:
    hits.extend(prober(ctx, attempts=attempts, interval_seconds=interval_seconds))
return tuple(hits)
```

### 4.2 四个判断入口怎么用这个元组

| 入口 | 位置 | 用法 | 为什么 |
| --- | --- | --- | --- |
| 扫层 | `NavigationExecutor.detect_layer` | 域探针结果与 `_PAGE_CHECKERS` 逐页结果合并，按 `depth_of` 降序 | 浮窗比演习页深，排前面 |
| 标签切换确认 | `NavigationExecutor._enter_tab` | checker 必须**严格相等**：`read_sortie_layer(...) == (PageName.X,)` | 浮窗在场时返回 `(浮窗, 演习)`，用 `in` 会误判「已经切过去了」 |
| 域页面到达确认 | `NavigationExecutor._confirm_arrival` | 取 `max(layers, key=registry.depth_of)`，**最深层必须就是目标页** | 关浮窗若没真关掉，`(浮窗, 演习)` 里含演习，用 `in` 会误判到达 |
| 主页是否干净 | `home.mark_popups_settled` | `read_home_layer(ctx, attempts=1) != (PageName.HOME,)` 就直接返回 | 只认「屏幕上只剩干净主页一层」 |

`_DOMAIN_PAGES` 现为 14 项（新增 `PageName.EXERCISE_RIVAL_CONFIRM`），`_PAGE_CHECKERS` 17 项。

### 4.3 页面与导航边（已落地）

| 从 | 到 | 动作 | tab | confirm |
| --- | --- | --- | --- | --- |
| `HOME` | `EXERCISE` | `HomePage(ctx).go_to(Target.SORTIE)` | `'exercise'` | True |
| `SORTIE_MAP` | `EXERCISE` | `SortiePage(ctx).go_to(SortieTab.EXERCISE)` | — | True |
| `EXERCISE` | `EXERCISE_RIVAL_CONFIRM` | `ExercisePage(ctx).select_rival(int(params['rival']))` | — | True |
| `EXERCISE_RIVAL_CONFIRM` | `EXERCISE_PREPARATION` | `ExercisePage(ctx).click_overlay_challenge(exercise.read_overlay_challenge_center(ctx))` | — | True |
| `EXERCISE_RIVAL_CONFIRM` | `EXERCISE` | `ExercisePage(ctx).click_overlay_close(exercise.read_overlay_close_center(ctx))` | — | True |
| `EXERCISE_PREPARATION` | `EXERCISE` | `BattlePreparationPage(ctx).go_back()` | — | True |

- `HOME → EXERCISE` 必须是**一跳**：`walk_forward` 只在 `len(path) == 1` 时把 `edge.tab` 交给 `_enter_tab`；
  走 `HOME → SORTIE_MAP → EXERCISE` 会让 tab 丢失。
- `_TABS` 新增 `PageName.EXERCISE: {'exercise': NavTab(...)}`，用于「首页点出征」之后把顶栏切到演习标签，
  并顺带确认浮窗没弹出来（checker 是严格相等）。
- `navigate_to(EXERCISE_RIVAL_CONFIRM, rival=N)` 的 N **必填**，只接受 1/2/3/4/5；越界在点任何东西之前抛 `ValueError`。

  只有冷启动栈空停在准备页时 `navigate_back()` 报「导航栈为空」（安全，不坏栈），调用方用 `navigate_to(EXERCISE)` 兜底。
- `EXERCISE_PREPARATION → EXERCISE` 暂时用 `BattlePreparationPage.go_back()` 的历史坐标
  `CLICK_BACK = (0.0313, 0.0528)`，待补返回按钮模板与 ROI 后改成 `expect_template_center(...) or CLICK_BACK`。
